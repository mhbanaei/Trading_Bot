# فاز ۳ — هارنس بکتست

وضعیت: **پیاده‌شده و اجراشده روی دادهٔ سینتتیک؛ روی دادهٔ واقعی اجرا نشد، چون
هیچ کندلی ذخیره نشده است.**
`nobitex_bot/backtest.py` به صرافی، موتور، `data.db` و معاملات واقعی وصل
نیست و `engine.py` آن را import نمی‌کند.

## ۱) چه چیزی مقایسه می‌شود

چهار بازو، با **خروج یکسان و هزینهٔ یکسان**، تا فقط «انتخاب» فرق کند:

| بازو | رتبه‌بندی | وتوی مکان ورود |
| --- | --- | --- |
| `change_24h` | تغییر ۲۴ساعته | خاموش — رفتار امروزِ موتور |
| `change_24h+veto` | تغییر ۲۴ساعته | روشن |
| `net_edge` | بازده انتظاری خالص | خاموش — اثر خالص رتبه‌بندی |
| `net_edge+veto` | بازده انتظاری خالص | روشن — خط لولهٔ فاز ۲ |

خواندن جدول: اگر ۲ و ۳ هر دو از ۱ بهتر باشند، مشکل «نبودِ وتو» بوده؛ اگر ۳ از
۲ بهتر باشد، خودِ رتبه‌بندی هم اثر دارد; اگر ۳ و ۴ برابر باشند، در این نمونه
وتو چیزی را عوض نکرده.

## ۲) هزینهٔ واقعی

- کارمزد `fee.taker_rate` پیش‌فرض **۰٫۲۵٪ هر طرف** (`--fee-pct`).
- اسلیپیج `risk.max_slippage` پیش‌فرض **۰٫۱٪ هر طرف** (`--slippage-pct`)،
  مستقیماً در قیمت پرشدن اعمال می‌شود: خرید `open×(1+slip)`، حد ضرر
  `stop×(1−slip)`، تایم‌اوت `close×(1−slip)`.
- اسپرد فقط با `--spread-pct`؛ کندل‌های ذخیره‌شده دفتر سفارش ندارند، پس
  پیش‌فرض صفر است و این در گزارش و JSON نوشته می‌شود (نه پنهان).
- `net_pct = (exit/entry − 1)×100 − (2×fee + spread)`. اسلیپیج دوباره کم
  نمی‌شود چون در قیمت‌ها هست.

## ۳) قواعد ضد تقلب

1. **ورود در open کندل بعدی** — تصمیم روی کندل بستهٔ `t`، پرشدن با
   `open[t+1]`. با تست `test_evidence_has_no_future_data` هم ثابت شده که
   Evidence از سری بریده‌شده تا همان کندل عیناً یکسان است.
2. **لمس هم‌زمان تارگت و استاپ = استاپ.** OHLC نمی‌گوید کدام اول بود؛
   فرض کردن برد، همهٔ بازوها را به‌طور مصنوعی خوب نشان می‌دهد.
3. **بدون lookahead در مقاومت:** سقف از high کندل‌های `i−lookback .. i−2`.
4. **`p_up` از آیندهٔ خودِ معامله نمی‌آید:** نرخ برخورد اولیهٔ تجربی روی
   کندل‌های *قبل از* تصمیم، با همان تارگت/استاپ و همان `max_hold`، نمونه‌گیری
   هر ۵ کندل. این «کالیبراسیون» نیست و در گزارش به‌عنوان روش写明 شده است.
5. **`top_gainer` فقط ثبت می‌شود** — همان قرارداد فاز ۲.

## ۴) منبع داده و یافتهٔ مهم

| مسیر | وضعیت |
| --- | --- |
| `--db data/trading_bot.db --symbols …` | کار می‌کند، ولی **جدول `candles` صفر ردیف دارد** (هر دو DB پروژه) |
| `--csv path.csv` (چندبار) | کار می‌کند؛ ستون‌های `timestamp/time/ts/date` + OHLCV |
| `--synthetic` | فقط برای تست خودِ هارنس؛ برچسب `synthetic` می‌خورد |

**ریشه:** `Storage.upsert_candle` وجود دارد اما **هیچ فراخواننده‌ای در کل
پروژه ندارد** — یعنی این نسخه از ربات کندل‌ها را ذخیره نمی‌کند. تا وقتی
ذخیره‌سازی یا اکسپورت CSV اضافه نشود، بکتست روی دادهٔ واقعی ممکن نیست.
(این یک کمبود زیرساختی است، نه باگ این هارنس.)

## ۵) اجرا

```bash
python -m nobitex_bot.backtest --synthetic --bars 800
python -m nobitex_bot.backtest --db data/trading_bot.db --timeframe 15m --symbols BTCIRT,ETHIRT
python -m nobitex_bot.backtest --csv a.csv --csv b.csv --timeframe 15m --json reports/bt.json
```

گزینه‌های مؤثر: `--slots` (تعداد موقعیت هم‌زمان)، `--max-hold`،
`--max-extension-atr`، `--min-p-up`، `--spread-pct`، `--fee-pct`،
`--slippage-pct`.

خروجی: جدول خلاصه + (اختیاری) JSON کامل شامل هر معامله، تنظیمات، روش‌ها و
Policy. ستون‌ها: `trades, win_rate, avg_net_pct, total_net_pct,
profit_factor, max_drawdown_pct, stop_rate, target_rate`.

## ۶) آنچه این فاز ثابت نمی‌کند

- **هیچ ادعای سوددهی.** اجرای سینتتیک فقط نشان می‌دهد هارنس کار می‌کند؛
  اعدادش شاهد هیچ رفتاری نیستند و نقل‌کردنشان به‌عنوان نتیجه ممنوع است.
- `total_net_pct` جمع بازده معاملات با نوتاسیون ثابت است، نه بازده مرکب.
- مدل اجرا ساده است: پرشدن کامل، بدون صف سفارش، بدون عمق بازار، بدون
  فاندینگ/کارمزد بازار.
- سوگیری انتخاب بازار و رژیم فقط با دادهٔ واقعی چند ماه دیده می‌شود.

## ۷) گام بعد

1. ذخیرهٔ کندل (فراخوانی `upsert_candle` از collector) یا اکسپورت CSV از
   تاریخچهٔ نوبیتکس، تا هارنس روی دادهٔ واقعی اجرا شود.
2. پس از آن: walk-forward و مقایسهٔ نمونه‌های مختلف؛ فقط با عدد مثبتِ تکرارشدنی
   سراغ اتصال pipeline به موتور (فاز ۴) برویم.
